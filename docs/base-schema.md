# 多维表格模板结构

GitHub 不能直接托管一个可运行的飞书多维表格，因此仓库用本文档版本化模板结构。部署者需要在自己的飞书空间创建一个 Base，并建立以下四张表。字段名必须与本文一致，脚本会按名称读取。

## 1. 项目任务

定义团队在做什么，以及正常情况下每天应该完成多少。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 任务/关键产物 | 文本（主字段） | 任务名称 |
| 日任务基线 | 数字 | 单人单日基准产量 |
| 单位 | 文本 | 条、张、段等 |
| 任务分类 | 单选 | 数据标注、数据处理、其他 |

## 2. 标注日报

团队成员每天提交一行，日报和周报均从这里汇总。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 日报记录 | 文本（主字段） | 建议填写“日期-姓名-任务” |
| 提交人 | 人员（单选） | 实际提交者 |
| 关联任务 | 关联记录 | 关联“项目任务” |
| 任务类型 | 单选 | 数据标注、数据处理、其他 |
| 当日完成量 | 数字 | 当日产出 |
| 单位 | 文本 | 产出单位 |
| 当日投入时间(天) | 数字 | 例如 0.5、1.0 |
| 基线达成率 | 百分比 | 完成量与基线的比值 |
| 提交日期 | 日期 | 报表归属日期 |

## 3. 团队人员

用于判断谁应提交日报，以及生成未提交提醒。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 成员说明 | 文本（主字段） | 显示名称或备注 |
| 人员 | 人员（单选） | 飞书成员 |
| 是否在岗 | 单选 | 工作中、已离岗；默认工作中 |

## 4. 标注指标

保存数据库同步后的库存、产出、正样本与目标预测。建议预置“人员轨迹、人体检测、人员倒地-学校、人员倒地-外部数据源、攀高、吸烟、打电话、剧烈运动”八行。

| 字段 | 类型 |
| --- | --- |
| 任务名称 | 文本（主字段） |
| 已标注、正样本、本周正样本、待标注、目标 | 数字 |
| 正样本率 | 百分比 |
| 平均标注量 | 数字 |
| 正样本覆盖人数、本周正样本覆盖学生 | 数字 |
| 待标注数据中没有正样本的学生人数 | 数字 |
| 预计可达到的正样本数 | 数字 |
| 达到目标还需天数、标注完毕还需天数 | 数字 |
| 关联项目任务 | 关联记录，关联“项目任务” |
| 最后更新时间 | 系统更新时间 |

## 环境变量映射

创建完成后，从 Base URL 获取 Base token，并从每张表的 URL 获取 table ID：

```dotenv
ANNOTATION_BASE_TOKEN=replace_me
ANNOTATION_PROJECT_TABLE_ID=replace_me
ANNOTATION_DAILY_TABLE_ID=replace_me
ANNOTATION_STAFF_TABLE_ID=replace_me
ANNOTATION_METRICS_TABLE_ID=replace_me
```

`ANNOTATION_RECORD_MAP_JSON` 将数据库指标 code 映射到“标注指标”的真实记录 ID。`人体检测` 仅用于日报展示，当前参考 SQL 不会自动更新它，因此无需加入映射。

```dotenv
ANNOTATION_RECORD_MAP_JSON={"trail":"record_id","fallDetect_school":"record_id","fallDetect_external":"record_id","climbDetect":"record_id","smokeAlarm":"record_id","calling":"record_id","strongExercise":"record_id"}
```

不要把真实 token、table ID、record ID 或 webhook 提交到 GitHub。
